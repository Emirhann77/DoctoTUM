# CareConnect End-to-End Implementation Plan

> **For agentic workers:** executed natively in one overnight session (owner asleep: decide, record, do not ask). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A signed-in person can use every page against a real Supabase project: their own profile, symptom checks, doctors, appointments, prescriptions, pharmacy orders and SOS alerts are stored and read back, and the backend knows who they are from a verified token.

**Architecture:** The browser keeps talking to Supabase directly for simple rows the person owns (row-level security already guards them) and to FastAPI for anything with rules across tables. FastAPI verifies the Supabase access token, then reads and writes through PostgREST *as that user* (anon key + their token), so row-level security stays the last line of defence. With no Supabase configured, the same routes run on an in-memory store so tests and keyless development still work.

**Tech stack:** FastAPI, Pydantic v2, httpx, python-jose; Supabase (Postgres 17, PostgREST, Auth); static HTML + plain JS served by Next.js from `public/`; pytest, `node --test`.

**Spec:** this conversation (owner's messages of 2026-11-17/18). Summary: end to end working app; commit on a branch, never push; OpenAI key may be used sparingly; no Stripe testing; payments, video calls and emergency dispatch stay simulated.

## Global constraints

- Never push. Commit per task on `feat/end-to-end`.
- No secret in a committed file. Test-user credentials live only in `.env.local`.
- OpenAI: at most a handful of live calls in total; every automated test runs in mock mode.
- A client-supplied `user_id` is never trusted. Identity comes from the verified token only.
- Never decode a token without verifying it.
- Anything simulated says so on screen. In particular the SOS page must not claim that help is on the way.
- Unknown or failed input in a medical decision routes to a clinician, never to self-care (existing rule).
- New user-visible strings get keys in all five locales (en, de, tr, es, fr). Legacy hard-coded English on pharmacy/profile/plans/sos is left as is unless the line is touched.
- Values interpolated into HTML go through an escape helper.
- Specialist ids are strings (Supabase UUIDs; `"1"`… in the in-memory store).

## Review focus

1. Expired or tampered token on a write → 401, nothing written, page sends the person to login.
2. User A asking for or cancelling user B's appointment/order/alert → 404, in both stores.
3. Booking in the past, or twice for the same time → 422 / 409.
4. Supabase unreachable mid-request → 503 with a plain message; the page shows an error, not fake success.
5. A brand-new account with no rows anywhere → every page renders an empty state, no demo person's data.
